# Tuftsguessr for JumboCode

Tuftsguessr is a GeoGuessr-inspired game about identifying buildings on the
Tufts University campus. Players see increasingly revealing images of a
building and try to guess its name before the round ends.

## How to play

1. Open the player page at `/` and enter a team name.
2. Open `/guess` and wait for the admin to start a round.
3. Use the campus map and the building search list to choose the building
   shown in the clue.
4. You can make up to two guesses per round. A correct guess adds the points
   currently shown on the image; an incorrect guess does not add points.
5. The image changes every 15 seconds. The round awards:
   - Image 1: 100 points
   - Image 2: 50 points
   - Image 3: 25 points
   - Image 4: 5 points
   - Final reveal: 0 points

The admin controls the game from `/secret-admin-board`. Opening that page
clears the current round. Choose **Start Game**, then use **Next** to advance
through the clues. **Clear teams & scores** removes every team before a new
game. The admin board shows the current image, timer, scoreboard, and recent
guesses, and plays a sound when a team guesses correctly.

## Running locally

### Requirements

- Node.js and npm
- An Upstash Redis database (the free tier is enough)

### Setup

Install dependencies:

```bash
npm install
```

Create a `.env.local` file in the project root with your Upstash Redis REST
credentials:

```env
KV_REST_API_URL=https://your-database.upstash.io
KV_REST_API_TOKEN=your-token
```

`UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` also work. These values
are secret: they stay on the server and are never sent to the browser.

Start the development server:

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in a browser. For a
production build, use:

```bash
npm run build
npm start
```

## Deploying to Vercel

1. In the Vercel project, open **Storage**, choose **Upstash** (Redis) from
   the Marketplace, create a free database, and connect it to the project.
   Vercel adds the `KV_REST_API_*` environment variables automatically.
2. Redeploy so the new variables take effect.
3. Open `/secret-admin-board`. If Redis isn't connected, the page shows an
   error that says so.

## How the game works

- `lib/clues.ts` defines the ordered rounds. Each clue has a `slug` and a
  `building_id`.
- `lib/buildings.ts` maps building IDs to the names shown to players.
- Game state lives in Redis and is read and written only through the API
  routes in `app/api/`. See `lib/store.ts` for the key layout.
- The admin browser runs the 15-second timer and sends each image change to
  `/api/admin/state`. Keep the admin board open for the whole game.
- Players' phones check `/api/state` every 1.5 seconds; the admin board checks
  every second. Polling pauses while a tab is in the background.
- Players submit guesses to `/api/guess`. The server checks the answer, limits
  each team to two guesses per round, and awards the points currently shown.
- The final image displays the building name and ends guessing for that round.

## Adding and storing clue images

Store clue images in `public/photos/`. Each clue needs exactly four JPEG files
with this naming pattern:

```text
public/photos/<slug>_1.jpg
public/photos/<slug>_2.jpg
public/photos/<slug>_3.jpg
public/photos/<slug>_4.jpg
```

For example, the clue `{ slug: "granoff", building_id: 56 }` requires:

```text
public/photos/granoff_1.jpg
public/photos/granoff_2.jpg
public/photos/granoff_3.jpg
public/photos/granoff_4.jpg
```

Image requirements:

- Use `.jpg` files; the extension is part of the path generated by the game.
- Use a lowercase slug with underscores when needed, matching the `slug` in
  `lib/clues.ts`.
- Number files from `_1` through `_4` with no missing numbers.
- Place the most zoomed-out or least revealing image at `_1` and the final
  building-reveal image at `_4`.
- Keep image dimensions and orientation consistent within a clue so the board
  does not jump as images change.

After adding the files, add the clue's slug and building ID to
`lib/clues.ts`. The building ID must also exist in `lib/buildings.ts`; otherwise
the answer name cannot be displayed correctly.

The `public/photos_2025/` directory contains an older set of images. The
current game loads images from `public/photos/` unless the image path logic is
changed.
